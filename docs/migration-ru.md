# Переезд «Книги рода» на российский хостинг (подготовка)

Цель: сайт, сервер и база на российском сервере, чтобы подключить оплату Альфа-Банка и чтобы приложение открывалось у людей в России без VPN. Делаем так же, как с Кики (VPS, свой домен .ru).

## Что где живёт сейчас и куда переезжает

| Часть | Сейчас | После переезда |
|---|---|---|
| Сайт (приложение) | GitHub Pages | nginx на российском сервере, новый адрес .ru |
| Сервер `kniga-api` | Vercel (serverless) | Node-процесс `server.mjs` под systemd за nginx |
| База (книги синхронизации, коды доступа, письма, пуши, комнаты) | Upstash Redis по REST (за рубежом) | свой Redis на том же сервере (`REDIS_URL`) |
| Оплата | шлюз Альфа-Банка (российский) | тот же шлюз, адрес сайта и обратные ссылки на новом домене |
| Планировщик пушей | Vercel cron и cron-job.org | cron сервера, раз в час |
| Вход через платформу курсов | Supabase (`PLATFORM_SUPABASE_URL`) | **пока остаётся за рубежом**: проверить доступность из России, при блокировках переносить отдельно |
| ИИ | выключен (`AI_ENABLED`) | остаётся выключенным, ключи при включении: российский провайдер предпочтительнее |
| Push-уведомления | web-push через сервисы Google/Apple | перепроверить доставку на телефонах в России |

## Что уже подготовлено в коде (ветка `claude/ru-hosting-prep`)
- `kniga-api/lib/redis-native.js` – свой клиент Redis (RESP), включается переменной `REDIS_URL`; Upstash остаётся запасным вариантом. Тест: `node test-redis-native.mjs`.
- `kniga-api/server.mjs` – боевой запуск всех адресов `/api/*` (лимит тела 3 МБ, `/health`, остановка по сигналу). Тест: `node test-server.mjs`.
- `kniga-api/migrate-redis.mjs` – перенос данных из Upstash в свой Redis (читает, ничего не удаляет, пробный запуск `--dry`). Тест: `node test-migrate.mjs`.
- `deploy/ru/` – `env.example`, `nginx.conf.example`, `kniga-api.service`, `kniga-push-tick.cron`, `deploy.sh` (с сохранением прежней версии) и `rollback.sh`.

## Порядок переезда
1. **Домен и сервер** (нужны твои аккаунты и оплата): домен .ru и VPS (можно тот же VDSINA, что у Кики, или отдельный). Для Книги рода хватит самого небольшого тарифа.
2. **Сервер:** установить nginx, Node 24, Redis, certbot; создать пользователя `kniga`; положить `deploy/ru/*` на места; заполнить `/etc/kniga-api.env`.
3. **Пробный запуск без людей:** `node migrate-redis.mjs --dry`, потом сам перенос данных, потом сайт на новом адресе, проверка тестовой оплаты на тестовом шлюзе Альфа-Банка.
4. **Банк:** сообщить Альфа-Банку новый адрес сайта и адреса возврата, получить боевые доступы (письмо: `kniga-api/ПИСЬМО_АЛЬФА_БАНК.docx`).
5. **Для людей:** у приложения новый адрес, поэтому данные в браузере старого адреса не переедут сами. Как у Кики: на старом адресе баннер и тур «Сохранить книгу файлом», на новом загрузка файла. Платные восстанавливают книгу из облака по коду доступа.
6. **Переключение:** `VITE_API_BASE` и `APP_ORIGINS` на новый адрес, пересобрать, выложить; старый адрес оставить как переходник на время.

## Риски
- Новый адрес = новое хранилище браузера: у людей без сохранённого файла локальные книги не появятся сами. Поэтому тур с файлом обязателен.
- Токены доступа подписаны `ACCESS_SECRET`: на новом сервере он должен быть тем же, иначе оплатившие потеряют доступ.
- Supabase и push из России могут работать нестабильно: проверить на телефонах до переключения.
