# Студия Дарины (`studio/`)

Мобильное приложение-чеклист с идеями контента для двух Instagram-аккаунтов Дарины:
`rod` — Книга Рода (@darina_balanuca), `zhi` — @zhiphotos. Статический сайт без сборки,
публикуется на GitHub Pages workflow-ом `.github/workflows/static.yml` (деплой с `main`).

## Как добавлять идеи

Все пункты лежат в `studio/data.json`: `{ "updated": "ГГГГ-ММ-ДД", "items": [...] }`.

```json
{ "id": "zhi-reels-31", "acc": "zhi", "sec": "reels",
  "title": "Хук — первая строка, которую видно в списке",
  "text": "Что внутри, сценарий или слайды, хвост. Переносы строк через \n",
  "tag": "охват", "added": "2026-10-15" }
```

- `sec`: `pins` (закрепы), `reels`, `carousels`, `threads`, `ideas` (её черновики, оформленные в посты), `fixes` (что поправить), `pains` (боли аудитории).
- `tag`: короткая метка — `охват` / `подписки` / `доверие` для хуков, `польза` / `споры` / `мифы` / `личный опыт` для Threads, любое короткое слово для остального.
- `id` уникальный и **никогда не меняется и не переиспользуется**: по нему в браузере хранятся её отметки «сделано» и «убрано». Новые пункты получают следующий номер в своей серии.
- Новые пункты добавляй **в конец** массива и обновляй `updated`. Всё, чьего `id` она ещё не видела, приложение само покажет в разделе «Новое».
- Ничего не удаляй из `data.json`, чтобы убрать пункт у неё: она убирает сама. Удалять можно только по её просьбе.

## Отчёт от Дарины

В приложении (⋯ → «Скопировать отчёт для Claude») она копирует в чат список сделанного (`✓ [id] …`),
убранного (`× [id] …`) и своих идей (`+ [раздел] …`). Свои идеи оформляй в полноценные пункты
(хук, наполнение, хвост) и добавляй в `data.json` с новыми `id`.

## Правила контента

Факты о Дарине — только из её слов. Чего не знаешь — пиши в [квадратных скобках].
Хуки — под холодного зрителя: первая фраза про него, продукт и кодовое слово только в хвосте.

**Тон — спокойствие, не давление** (её главный принцип с октября 2026). Не пугать «пока не поздно»,
не давить на боль, без сложных слов и капса. Боль — одной строкой, дальше — что сделать, чтобы стало легче.
Продажа = ясность: какую проблему решаю, что за продукт, зачем идти. Видео: она, кофе, одна мысль,
без орущей музыки и эффектов. Четвёртый фильтр хука: после него спокойнее, а не тревожнее.
Не повторяй хуки, которые уже есть в `data.json`.

## Кики (продаётся в @zhiphotos)

Приложение для мам: https://kiki-m-m-app-grok.vercel.app/ — Дарина сделала его сама с ИИ, не зная кода,
«устала каждый день придумывать игры для сына», и каждый день улучшает вместе с мамами (~30 в тесте).
Внутри: карточки-игры по возрасту (по минуте, по шагу); колоды по месту и силам («Лень» — мама лежит на диване,
«Готовлю», «Машина», «Парк», «Тихо», «Много энергии»); «нажми 3 раза — вытяни карту»; план игр на день;
режим сна с окном бодрствования по ритму малыша, нормы педиатра, напоминания на экран блокировки, белый шум,
кормление; импорт PDF из AnaBaby; синхронизация со вторым родителем; «Наш год»; огонёк; загадки для мам;
сказки (скоро). Ставится без App Store. Внутри есть карточки, ведущие в курс «Книга Рода».
Кодовое слово в контенте — КИКИ. Цена не решена — пиши [цена].
Главная мысль: «Ты не плохая мама — ты просто устала придумывать». Экран у мамы, не у ребёнка.

В Книге Роде Дарина планирует своё приложение-игру для заполнения книги (уютное хобби) и вайб-рилс
(сериал, чай, сканирование фото, оформление страниц на iPad).

Весь контент строится по её методике: скрытые мысли с конфликтом → новая надежда
(желание → симптомы → ложная причина → корень → новый механизм) → три фильтра хука
(эмоция, простота, новизна) → 10 вопросов убеждения. Threads делятся на пользу, споры, мифы,
личный опыт, и у каждой темы есть «почему подпишутся».
