# Серверная часть «Книги рода»: оплата, чеки, доступ

Маленький проект для Vercel (папка `kniga-api`). Принимает оплату через интернет-эквайринг Альфа-Банка, банк сам отправляет кассовый чек покупателю на почту, а приложение открывает программу автоматически.

## Как это работает

1. В приложении: «Купить» → почта для чека + отметки согласия (оферта, соглашение, ПДн, рассылка необязательно) → `POST /api/checkout`.
2. Сервер регистрирует заказ в банке (`register.do`) на **2 026 ₽** с корзиной для чека (`orderBundle`: услуга, без НДС, полный расчёт), записывает согласия в параметры заказа и отдаёт адрес платёжной страницы банка.
3. Покупатель платит на странице банка. Банк возвращает его на `/api/pay-return`.
4. Сервер спрашивает банк о заказе (`getOrderStatusExtended.do`). Только если банк подтвердил оплату (статус 2) именно на 2 026 ₽, сервер подписывает токен доступа и возвращает человека в приложение. Подделать возврат нельзя.
5. Приложение кладёт токен в память телефона и открывает все уроки. При каждом запуске оно спрашивает сервер (`/api/verify`): токен подписан, срок не вышел, платёж не возвращён.
6. Новое устройство: «Уже оплатили?» → номер заказа и почта из чека → `/api/claim`.

Хранилища и базы данных не нужно: заказы лежат у банка, токен подписан секретом.

## Что сделать вам (один раз)

### 1. Альфа-Банк
- Подать заявку на интернет-эквайринг для нового сайта «Книга рода». Черновик письма: `ПИСЬМО_АЛЬФА_БАНК.docx` (на странице сайта «О сервисе» уже есть всё, что банк просит проверить).
- Получить доступы к **тестовому** шлюзу (логин `r-…-api`, пароль), потом к боевому.
- Попросить банк включить **фискализацию (онлайн-кассу банка)**, чтобы чек уходил покупателю автоматически. Уточнить у банка или бухгалтера систему налогообложения ИП (для переменной `ALFA_TAX_SYSTEM`).

### 2. Vercel
1. Новый проект из этого репозитория, **Root Directory: `kniga-api`**, Framework: Other.
2. Переменные окружения (Settings → Environment Variables):

| Переменная | Значение |
| --- | --- |
| `ALFA_BASE_URL` | тест `https://alfa.rbsuat.com/payment/rest`, бой `https://pay.alfabank.ru/payment/rest` |
| `ALFA_API_USER` | логин API |
| `ALFA_API_PASSWORD` | пароль API |
| `ACCESS_SECRET` | любая длинная случайная строка, минимум 24 символа (подпись токенов; потеряете – доступ у всех придётся выдавать заново) |
| `APP_ORIGINS` | адрес сайта приложения без пути, например `https://zhiphotos.github.io` (можно несколько через запятую) |
| `ALFA_TAX_SYSTEM` | 0 общая, 1 УСН доходы, 2 УСН доходы минус расходы, 4 ЕСХН, 5 патент |
| `ALFA_VAT_TYPE` | 0 без НДС (по умолчанию) |
| `PRICE_RUB` | 2026 (по умолчанию) |
| `ACCESS_DAYS` | 365 (по умолчанию) |
| `AI_API_KEY` | ключ ИИ-сервиса (OpenAI-совместимого, например Polza.ai) для кнопки «Разметить с помощью ИИ» в «Текст → страницы». Без ключа кнопка работает по правилам без ИИ |
| `AI_BASE_URL`, `AI_MODEL` | необязательно: по умолчанию Polza.ai и google/gemini-3.1-flash-lite |

Секреты вписываются только сюда, в код и в git они не попадают.

3. После деплоя получится адрес вида `https://kniga-roda-api.vercel.app`.

### 3. Приложение
В `kniga-src` создать файл `.env.production` со строкой `VITE_API_BASE=https://kniga-roda-api.vercel.app`, пересобрать (`npm run build:pages`) и выложить. После этого в окне покупки появится оплата картой.

### 4. Проверка
- Сначала весь путь на тестовом шлюзе тестовой картой из письма банка.
- Убедиться, что чек пришёл на почту (для теста банк может его не отправлять).
- Потом переключить `ALFA_BASE_URL`, логин и пароль на боевые.
- Когда оплата заработает, убрать тестовый код `КНИГА` из `kniga-src/src/lib/rod/config.ts` (`ACCESS_CODES`): он виден в коде приложения.

## Проверка без банка
`node test-flow.mjs` запускает поддельный шлюз и прогоняет всю цепочку: заказ, чек, согласия, возврат из банка, токен, подделку токена, вход по номеру заказа, возврат денег. Все проверки должны быть `ok`.

## Что не проверено
Настоящий шлюз Альфа-Банка с вашими доступами. Формат корзины и признаки чека (`orderBundle`) соответствуют документации RBS, но банк может потребовать другие коды или ставку НДС. Это решается переменными и парой строк в `lib/alfa.js`.


## Напоминания (пуши) и семейный доступ

Им нужно хранилище и ключи. Ничего из этого нельзя класть в git.

1. **Upstash Redis** (бесплатного тарифа хватит): создать базу, скопировать REST URL и токен в переменные `UPSTASH_REDIS_REST_URL` и `UPSTASH_REDIS_REST_TOKEN`.
2. **Ключи VAPID** для пушей: `npm install`, затем `node generate-vapid.mjs`. Публичный и приватный ключи вписать в `VAPID_PUBLIC_KEY` и `VAPID_PRIVATE_KEY` (и по желанию `VAPID_SUBJECT=mailto:darinazizina@gmail.com`).
3. **Планировщик раз в час.** Vercel на бесплатном тарифе умеет cron только раз в сутки, поэтому используйте cron-job.org (бесплатно) или QStash: запрос `GET https://<ваш-проект>.vercel.app/api/push-tick?key=<CRON_SECRET>` каждый час. `CRON_SECRET` – длинная случайная строка в переменных Vercel.
4. Когда включите оплату, поставьте `REQUIRE_PAID=1`: тогда ссылку для родственников сможет создать только тот, у кого открыта программа.

Как это устроено:
- Приложение спрашивает у сервера публичный ключ (`/api/push-config`), подписывает телефон и отправляет подписку (`/api/push-subscribe`). Время, дни недели и часовой пояс хранятся вместе с подпиской.
- Каждый час `/api/push-tick` проходит по подпискам: кому сейчас выбранный час и день, кто сегодня уже не получал напоминание и не открывал приложение, тому уходит одно сообщение из `lib/push-messages.js`. Мёртвые подписки стираются сами.
- Семейная комната: `room-create` (создать), `room-info` (кто приглашает), `room-submit` (родственник присылает), `room-inbox` и `room-ack` (владелец забирает и убирает). Ключи хранятся в виде хешей, фото до 450 КБ, не больше 200 входящих и 40 отправок с одного адреса в сутки.

Проверка без внешних сервисов: `node test-family.mjs` (25 проверок) и `node dev-server.mjs` для запуска всех функций у себя на компьютере (порт 3000, данные в памяти).
